# 性能可疑点清单（待设备空闲时验证）

> 本文件记录**尚未被测量证实**的性能判断。每条注明：现状、怀疑理由、怎么验、
> 验证后的结论该写回哪里。测完就删掉对应条目。

## 已修（留作记录，避免回退）

| 问题 | 修法 |
|---|---|
| `range` 上界的线性探上限按窗口大小取（`linear_max*8=64`），导致 64 元窗口被扫两遍 | 改成常量 8：窗口 ≤8 走线性探，>8 回退 `upper_bound_fast` |
| `len()` 每次都遍历 chunks 求和（旧 chunked 版） | 已随结构简化消失（现在是 `entries.len()`） |
| 追加快路径缺失 | 升序插入直接 `Vec::push`，省一次二分 |

## 待验证

1. **`RANGE_SCAN_MAX = 8` 是否最优**
   - 现状：固定 8；怀疑点：该值应≈一次块内二分的比较次数，块内元素分布不同时最优点会漂。
   - 验法：把它做成 `with_span_scan_max(n)` 临时参数，对 `--win` ∈ {8, 64, 1024} × 两种分布扫 0/4/8/16/32，看 `win` 与 `win-cur` 两列。

2. **块表大小与 L1/L2 的冲突**
   - 现状：块数 ≈ n（`W ≈ span/n`），n=1e5 时块表 ≈ 390 KB，超出 L1/L2 的常规容量。
   - 怀疑：`blocks[b]` 那一次随机加载是 n 大时随机查询的主要成本（也解释了为什么 n=1e5 随机查询 ≈20 ns 而 n=1e3 只要 ≈10 ns）。
   - 验法：把 `W` 放大 2×/4×/8×（块数变 n/2…n/8，块内扫 2–8 项），比较"块表加载 miss 减少"与"块内多扫几项"。这需要把 `W` 的取整倍数做成参数。

3. **聚簇块内二分能否再降**
   - 现状：块内元素 > `linear_max` 时块内二分（约 7 次比较）。
   - 怀疑：加二级锚（每块 8 格，`blocks2[b*8+minor]`）可把定位降到 1 次加载 + ≤8 项线性扫；kipphi 原版就有这一层，我删掉了。
   - 验法：现有 `handles_clustered_keys` 数据（100 键/组）上对比"块内二分"与"二级锚"，看随机查询是否从 ~6.5 ns 再降。

4. **`block_of` 的 f64 除法**
   - 现状：每次查询一次 `(k - base) / width`。
   - 怀疑：`W` 是 2 的幂，除以 2^k 在 f64 上是精确缩放；可换乘 `inv_width`，但需证明舍入不改变分块边界（否则会出现极罕见的错块）。
   - 验法：随机 1e8 个键，比较 `/ W` 与 `* (1/W)` 的 `floor` 结果是否完全一致；一致才换。

5. **`cursor_lower_bound/upper_bound` 的双比较循环**
   - 现状：循环条件比较一次，循环退出后再比较一次判断是否超限。
   - 怀疑：可重排为"先记录方向，循环内单比较 + 计数"，省一次比较/查询。
   - 验法：微基准 1e6 次顺序 `find_le_from`，比较改前改后。

6. **`RangeIter` 与 `slice::Iter` 的差别**
   - 现状：`RangeIter::next` 用 `split_first`（等价于 slice 迭代）；`window_split` 实测两者曾出现 34.6 vs 11.8 ns 的差异，属噪声。
   - 验法：同一份 spans，用 `span_iter` 与"手工 `&v[a..b]`"交替各跑 50 轮取中位数；若确有差，改成持有 `ptr/end` 的实现。

7. **插入的 memmove**
   - 现状：任意位置插入 O(n)。
   - 怀疑：批量写（导入）时即使乱序也是逐条 memmove；若提供 `extend_sorted(Vec)` 可一次排序 + 一次搬移。
   - 验法：构造 10% 乱序批量的导入负载，比较逐条 `insert` 与"排序后批量 extend"。

8. **时间窗负载缺失**
   - 现状：bench 的窗口按**元素序号**切 64 个，聚簇时会切在块中部（对抗性）。
   - 怀疑：真实播放窗按时间切、且与上一窗相邻，游标收益被当前窗口切法低估。
   - 验法：加"按时间跨度切窗"的负载（连续、有重叠），再比较 `win` 与 `win-cur`。

## 测量方法本身的坑（先修这个，再信数字）

- 当前 `bench` 单进程串行跑，机器降频/占用会让 `full < pos + iter` 这种不可能的不等式出现；
  出现即作废该轮。
- 建议：每轮先跑一次固定负载（类似 playbench 的 `[probe]`）记录设备状态；只保留
  probe 偏差 <20% 的轮次。
